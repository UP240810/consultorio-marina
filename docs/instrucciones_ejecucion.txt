INSTRUCCIONES PASO A PASO PARA EJECUTAR Y PUBLICAR EL PROYECTO
==================================================================

Este documento explica cómo dejar el proyecto funcionando en dos
escenarios:

  PARTE A. En tu computadora (modo desarrollo local)
  PARTE B. Publicar en internet con GitHub + Vercel + Supabase

Sigue los pasos EN ORDEN. No saltes pasos.
Si aparece un error, detente y revisa el paso anterior antes de
continuar.


==================================================================
REQUISITOS PREVIOS (antes de empezar)
==================================================================

1. Instalar Node.js versión 18 o superior
   - Ve a https://nodejs.org
   - Descarga la versión "LTS" (recomendada)
   - Instálala como cualquier programa (Siguiente → Siguiente → Instalar)
   - Para comprobar que quedó instalado, abre una terminal
     (CMD, PowerShell, Terminal de Mac/Linux) y escribe:

       node -v

     Debe mostrarte algo como "v18.x.x", "v20.x.x" o superior.
     Si no reconoce el comando, cierra y vuelve a abrir la terminal,
     o reinicia la computadora.

2. Instalar Git (si no lo tienes)
   - Ve a https://git-scm.com/downloads
   - Descarga e instala para tu sistema operativo
   - Comprueba con:

       git --version

3. Tener Python 3 instalado
   (se usa solo una vez para generar las 500 frases motivadoras)
   - Comprueba con:

       python3 --version

   - Si no lo tienes, descárgalo de https://www.python.org/downloads
   - En Windows, durante la instalación marca la casilla
     "Add Python to PATH".

4. Descomprimir el proyecto
   - Descomprime el archivo .zip del proyecto en una carpeta de
     tu computadora, por ejemplo:

       Documentos/consultorio-marina

   - Dentro debe verse la estructura principal:
       db/
       diagrams/
       docs/
       src/
       package.json
       README.md
       ...

5. Crear una cuenta gratuita en Supabase
   - Ve a https://supabase.com
   - Clic en "Start your project"
   - Regístrate con tu correo o con GitHub

6. Crear una cuenta gratuita en Resend (para envío de correos)
   - Ve a https://resend.com
   - Regístrate con tu correo

7. Crear una cuenta en GitHub (si no tienes)
   - Ve a https://github.com
   - Regístrate con tu correo

8. Crear una cuenta gratuita en Vercel
   (solo necesaria si vas a publicar en internet – Parte B)
   - Ve a https://vercel.com
   - Regístrate preferentemente con tu cuenta de GitHub
     (así se conectan automáticamente)


==================================================================
PARTE A. EJECUTAR EN TU COMPUTADORA (DESARROLLO LOCAL)
==================================================================

PASO 1. Abrir una terminal dentro de la carpeta del proyecto
--------------------------------------------------------------
1. Abre el explorador de archivos y entra a la carpeta donde
   descomprimiste el proyecto (ej. Documentos/consultorio-marina).

2. Abre una terminal ahí mismo:

   - Windows:
     Clic derecho dentro de la carpeta → "Abrir en Terminal"
     o "Abrir ventana de PowerShell aquí".

   - Mac:
     Abre la app "Terminal", escribe "cd " (con espacio),
     arrastra la carpeta del proyecto a la ventana de Terminal
     y presiona Enter.

   - Linux:
     Clic derecho dentro de la carpeta → "Abrir terminal aquí".

3. Verifica que estás en la carpeta correcta escribiendo:

       ls

   (o "dir" en Windows). Debes ver archivos como package.json,
   README.md, la carpeta src/, db/, diagrams/, etc.


PASO 2. Instalar las dependencias del proyecto
--------------------------------------------------------------
En la terminal, dentro de la carpeta del proyecto, escribe:

    npm install

Espera a que termine (puede tardar de 1 a 3 minutos la primera vez).
Al finalizar se crea la carpeta "node_modules".

Si aparece algún aviso en color amarillo (warnings), normalmente
puedes ignorarlos. Solo detente si aparece un error en rojo.


PASO 3. Crear tu proyecto en Supabase
--------------------------------------------------------------
1. Entra a https://supabase.com e inicia sesión.
2. Clic en "New Project".
3. Elige una organización (o crea una si es tu primera vez).
4. Completa los datos:
   - Name: consultorio-marina (o el nombre que prefieras)
   - Database Password: crea una contraseña segura y GUÁRDALA
     en un lugar seguro (la necesitarás si algún día quieres
     conectarte directo a la base de datos).
   - Region: elige la más cercana a ti (ej. East US, South America, etc.)
5. Clic en "Create new project".
6. Espera 1-2 minutos hasta que el estado del proyecto pase a
   "Active" / listo.


PASO 4. Ejecutar el esquema de la base de datos
--------------------------------------------------------------
1. Dentro de tu proyecto de Supabase, en el menú lateral izquierdo,
   busca y haz clic en "SQL Editor".
2. Clic en "New query" (o "New").
3. En tu computadora, abre el archivo:

       db/schema.sql

   (está dentro de la carpeta del proyecto).
4. Selecciona TODO el contenido (Ctrl+A / Cmd+A) y cópialo
   (Ctrl+C / Cmd+C).
5. Pégalo en el editor SQL de Supabase.
6. Clic en el botón "Run" (o presiona Ctrl+Enter / Cmd+Enter).
7. Debe aparecer un mensaje de éxito similar a:
   "Success. No rows returned".

   Si aparece un error:
   - Verifica que copiaste el archivo completo desde la primera
     hasta la última línea.
   - Asegúrate de no haber pegado texto extra.


PASO 5. Crear el usuario de la psicóloga (para iniciar sesión)
--------------------------------------------------------------
1. En el menú lateral de Supabase, ve a "Authentication".
2. Entra a la pestaña "Users".
3. Clic en "Add user" → "Create new user".
4. Completa:
   - Email: el correo con el que iniciará sesión Marina
   - Password: la contraseña que usará para entrar a la aplicación
5. Si aparece la opción "Auto Confirm User", márcala.
6. Clic en "Create user".
7. En la lista de usuarios, copia el "User UID" (es un código largo
   tipo uuid). Lo necesitarás solo si quieres cargar datos de
   ejemplo en el Paso 6.


PASO 6. (Opcional) Cargar pacientes de ejemplo
--------------------------------------------------------------
1. Abre el archivo db/seed.sql de tu carpeta del proyecto.
2. Busca TODAS las apariciones del texto:

       <TU_USER_ID>

   y reemplázalas por el User UID que copiaste en el Paso 5.
3. Copia el contenido completo del archivo.
4. En Supabase → SQL Editor → "New query", pega el contenido.
5. Clic en "Run".

Esto crea pacientes de prueba para que puedas explorar la
aplicación sin tener que dar de alta todo desde cero.


PASO 7. Obtener las llaves de conexión de Supabase
--------------------------------------------------------------
1. En el menú lateral de Supabase, ve a "Project Settings"
   (ícono de engrane, normalmente al final del menú).
2. Clic en "API".
3. Copia y anota estos tres valores (los necesitarás en el Paso 9):

   - Project URL
     → se usará como NEXT_PUBLIC_SUPABASE_URL

   - anon public  (bajo "Project API keys")
     → se usará como NEXT_PUBLIC_SUPABASE_ANON_KEY

   - service_role (bajo "Project API keys")
     → se usará como SUPABASE_SERVICE_ROLE_KEY

     IMPORTANTE: la llave service_role es secreta.
     Nunca la compartas ni la subas a GitHub.


PASO 8. Obtener tu llave de Resend (para correos)
--------------------------------------------------------------
1. Entra a https://resend.com e inicia sesión.
2. En el menú lateral ve a "API Keys".
3. Clic en "Create API Key".
4. Ponle un nombre (ej. "consultorio-marina") y confirma.
5. Copia la clave que empieza con "re_..."
   (solo se muestra una vez; guárdala en un lugar seguro).


PASO 9. Configurar las variables de entorno del proyecto
--------------------------------------------------------------
1. Dentro de la carpeta del proyecto busca el archivo:

       .env.example

2. Haz una copia y renómbrala a:

       .env.local

   Formas de hacerlo:
   - Windows: clic derecho → Copiar → Pegar → renombrar.
   - Mac / Linux (en la terminal):

         cp .env.example .env.local

3. Abre el archivo .env.local con un editor de texto
   (VS Code, Bloc de notas, TextEdit, etc.).

4. Reemplaza cada valor con los datos que obtuviste:

   NEXT_PUBLIC_SUPABASE_URL=          (Project URL del Paso 7)
   NEXT_PUBLIC_SUPABASE_ANON_KEY=     (llave "anon public" del Paso 7)
   SUPABASE_SERVICE_ROLE_KEY=         (llave "service_role" del Paso 7)
   RESEND_API_KEY=                    (llave del Paso 8)
   REMINDER_FROM_EMAIL="Consultorio Marina Velázquez <onboarding@resend.dev>"
   NEXT_PUBLIC_APP_URL=http://localhost:3000
   CRON_SECRET=                       (inventa un texto largo y aleatorio,
                                       ej. "miClaveSecretaConsultorio2026")
   DOCTOR_ALERT_EMAIL=                (correo de Marina para recibir
                                       alertas de factor de riesgo)

5. Guarda el archivo.

Notas:
- No dejes espacios antes o después del signo "=".
- No pongas comillas excepto donde ya aparecen en el ejemplo
  (REMINDER_FROM_EMAIL).
- El archivo .env.local NUNCA se sube a GitHub (ya está ignorado
  por el .gitignore del proyecto).


PASO 10. Generar las 500 frases motivadoras
--------------------------------------------------------------
En la terminal, dentro de la carpeta del proyecto, escribe:

    python3 scripts/generate_quotes.py

Debe aparecer un mensaje similar a:
"500 frases guardadas en src/lib/quotes.json".

Si el archivo ya existía, simplemente se regenera. No pasa nada.


PASO 11. Ejecutar el proyecto en modo desarrollo
--------------------------------------------------------------
En la terminal, dentro de la carpeta del proyecto, escribe:

    npm run dev

Espera a que aparezca un mensaje similar a:

    ✓ Ready in ... ms
    - Local: http://localhost:3000

Deja esta terminal abierta mientras uses la aplicación.
No la cierres ni presiones Ctrl+C todavía.


PASO 12. Abrir la aplicación en el navegador
--------------------------------------------------------------
1. Abre tu navegador (Chrome, Edge, Firefox, Safari, etc.).
2. Ve a la dirección:

       http://localhost:3000

3. Debes ver la pantalla de inicio de sesión con una frase
   motivadora del día y el símbolo Ψ.

4. Inicia sesión con el correo y la contraseña que creaste
   en el Paso 5.

5. Una vez dentro podrás usar:
   - Panel principal (resumen)
   - Agenda
   - Pacientes
   - Documentos
   - Estadísticas


PASO 13. Detener el servidor cuando termines
--------------------------------------------------------------
En la terminal donde está corriendo "npm run dev", presiona:

    Ctrl + C

Esto apaga el servidor local de forma segura.


==================================================================
PARTE B. PUBLICAR EN INTERNET (GITHUB + VERCEL + SUPABASE)
==================================================================

Antes de empezar esta parte:
- Completa la PARTE A al menos hasta el Paso 8
  (debes tener lista la base de datos en Supabase y la llave de Resend).
- Asegúrate de que el proyecto funciona correctamente en local
  (Paso 12).


PASO 14. Preparar el proyecto para GitHub
--------------------------------------------------------------
1. Abre una terminal dentro de la carpeta del proyecto
   (igual que en el Paso 1).

2. Verifica el estado de Git:

       git status

   Si ves muchos archivos en rojo/no rastreados, es normal la
   primera vez.

3. Agrega todos los archivos del proyecto
   (incluye diagramas, capturas y documentación):

       git add .

4. Crea el primer commit:

       git commit -m "Versión inicial del Consultorio Marina - POO, diagramas y documentación completa"

   Si Git te pide configurar nombre y correo, hazlo con:

       git config --global user.name "Tu Nombre"
       git config --global user.email "tu@correo.com"

   y vuelve a ejecutar el commit.


PASO 15. Crear el repositorio en GitHub
--------------------------------------------------------------
1. Entra a https://github.com e inicia sesión.
2. Clic en el botón "+" (arriba a la derecha) → "New repository".
3. Completa:
   - Repository name: consultorio-marina (o el nombre que quieras)
   - Description (opcional): Organizador de consultorio psicológico – Proyecto POO
   - Visibility: elige Private (recomendado) o Public
4. NO marques ninguna casilla de:
   - "Add a README file"
   - "Add .gitignore"
   - "Choose a license"
   (el proyecto ya trae su propio README, .gitignore y estructura)
5. Clic en "Create repository".


PASO 16. Subir el proyecto a GitHub
--------------------------------------------------------------
1. En la página del repositorio recién creado, GitHub te muestra
   un bloque de comandos bajo el título:

   "…or push an existing repository from the command line"

2. Copia los comandos que te muestra (serán similares a estos,
   pero con TU URL real):

       git remote add origin https://github.com/TU_USUARIO/consultorio-marina.git
       git branch -M main
       git push -u origin main

3. Pégalos en tu terminal (dentro de la carpeta del proyecto)
   y presiona Enter.

4. Si te pide autenticarte:
   - Puede abrirse el navegador para iniciar sesión con GitHub.
   - O pedirte usuario y un "Personal Access Token"
     (no uses tu contraseña normal de GitHub).
     Para crear un token: GitHub → Settings → Developer settings →
     Personal access tokens → Generate new token.

5. Espera a que termine el "push". Cuando finalice, recarga la
   página de tu repositorio en GitHub: debes ver todos los
   archivos (src/, db/, diagrams/, docs/, README.md, etc.).

6. Abre el README.md en GitHub. Debes ver:
   - Los badges de tecnologías
   - Las capturas del sistema
   - Los diagramas de base de datos, clases y patrones


PASO 17. Importar el proyecto en Vercel
--------------------------------------------------------------
1. Entra a https://vercel.com e inicia sesión
   (idealmente con la misma cuenta de GitHub).
2. Clic en "Add New..." → "Project".
3. En la lista de repositorios busca "consultorio-marina"
   (o el nombre que le pusiste) y clic en "Import".
4. Vercel detectará automáticamente que es un proyecto Next.js.
   No cambies nada en "Framework Preset" ni en
   "Build and Output Settings".


PASO 18. Configurar las variables de entorno en Vercel
--------------------------------------------------------------
1. En la misma pantalla de importación (antes de desplegar),
   busca la sección "Environment Variables".

   Si ya desplegaste antes, ve a:
   tu proyecto → Settings → Environment Variables.

2. Agrega UNA POR UNA las siguientes variables
   (usa exactamente los mismos valores de tu archivo .env.local,
   excepto NEXT_PUBLIC_APP_URL):

   Nombre                              Valor
   ----------------------------------  ------------------------------------------
   NEXT_PUBLIC_SUPABASE_URL            (igual que en local)
   NEXT_PUBLIC_SUPABASE_ANON_KEY       (igual que en local)
   SUPABASE_SERVICE_ROLE_KEY           (igual que en local)
   RESEND_API_KEY                      (igual que en local)
   REMINDER_FROM_EMAIL                 (igual que en local)
   CRON_SECRET                         (igual que en local o uno nuevo)
   DOCTOR_ALERT_EMAIL                  (igual que en local)
   NEXT_PUBLIC_APP_URL                 (déjalo vacío por ahora;
                                        se completa en el Paso 20)

3. Asegúrate de que cada variable esté marcada para los
   entornos Production, Preview y Development (o al menos
   Production).

4. Guarda los cambios.


PASO 19. Desplegar
--------------------------------------------------------------
1. Clic en el botón "Deploy".
2. Espera entre 1 y 3 minutos mientras Vercel construye el
   proyecto.
3. Cuando termine verás un mensaje de éxito y un enlace
   (botón "Visit" o "Continue to Dashboard").
4. Copia la URL que te asignó Vercel, por ejemplo:

       https://consultorio-marina.vercel.app

   o

       https://consultorio-marina-xxxx.vercel.app


PASO 20. Completar la URL pública
--------------------------------------------------------------
1. Ve a tu proyecto en Vercel → Settings → Environment Variables.
2. Edita la variable NEXT_PUBLIC_APP_URL y pega la URL que
   copiaste en el Paso 19 (sin diagonal "/" al final).

   Ejemplo correcto:
       https://consultorio-marina.vercel.app

3. Guarda los cambios.
4. Ve a la pestaña "Deployments".
5. En el despliegue más reciente, clic en los tres puntos (...)
   → "Redeploy".
6. Confirma el redeploy. Espera a que termine.


PASO 21. Verificar el cron de recordatorios
--------------------------------------------------------------
1. En tu proyecto de Vercel busca la sección "Cron Jobs"
   (puede estar en Settings → Cron Jobs o en una pestaña
   dedicada según la versión del panel).
2. Debe aparecer una tarea programada que apunta a:

       /api/cron/reminders

   y se ejecuta una vez al día.

   Esto ya viene configurado en el archivo vercel.json del
   proyecto; no necesitas crearlo manualmente.


PASO 22. Entrar a la aplicación publicada
--------------------------------------------------------------
1. Abre en tu navegador la URL de tu proyecto, por ejemplo:

       https://consultorio-marina.vercel.app

2. Inicia sesión con el correo y la contraseña del usuario
   que creaste en el Paso 5.

3. Ya puedes usar la aplicación desde cualquier dispositivo
   con conexión a internet.


==================================================================
NOTAS IMPORTANTES Y SOLUCIÓN DE PROBLEMAS
==================================================================

Seguridad
---------
- Nunca subas a GitHub el archivo .env.local.
  Contiene llaves secretas. El archivo .gitignore del proyecto
  ya está configurado para ignorarlo automáticamente.
- La llave SUPABASE_SERVICE_ROLE_KEY es especialmente sensible:
  solo debe existir en el servidor (Vercel / tu máquina local),
  nunca en el código del cliente.

Correos a pacientes
-------------------
- Para que un paciente reciba el enlace de confirmación de cita
  y la encuesta post-sesión, debe tener registrado su correo
  electrónico en su ficha (Pacientes → [paciente] → Editar).

Cambios en variables de entorno
-------------------------------
- Cada vez que modifiques una variable de entorno en Vercel
  debes hacer "Redeploy" para que el cambio tome efecto.

Errores frecuentes
------------------
1. "Invalid API key" o errores de conexión a Supabase
   → Revisa que las tres llaves (URL, anon, service_role)
     estén copiadas completas y sin espacios de más.

2. La aplicación abre pero no deja iniciar sesión
   → Verifica que el usuario exista en Supabase → Authentication
     → Users y que hayas marcado "Auto Confirm User".

3. Los correos no se envían
   → Comprueba que RESEND_API_KEY esté bien escrita y que
     el paciente tenga correo registrado.
   → En el plan gratuito de Resend solo puedes enviar a tu
     propio correo hasta que verifiques un dominio.

4. Los diagramas o capturas no se ven en GitHub
   → Asegúrate de haber hecho "git add ." e incluir las
     carpetas diagrams/ y docs/images/ en el commit.
